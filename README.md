## 🔍 OOP Concepts Covered

> Each concept is implemented with real code examples — not just theory.

<br/>

### 🔒 Abstraction
**What it is:** Hiding internal complexity and exposing only what's necessary.  
**Why it matters:** Cleaner APIs, simpler interfaces, reduced coupling between components.  
**Real use:** When you call `System.out.println()`, you don't know what's inside — that's abstraction.  
📁 `Abstraction/`

---

### 📦 Encapsulation
**What it is:** Bundling data (fields) and behavior (methods) together, restricting direct access.  
**Why it matters:** Prevents unintended data corruption; enforces controlled interaction via getters/setters.  
**Real use:** The ATM only lets you withdraw — it never gives you raw access to the vault.  
📁 `Encapsulation/` · `simple atm.java`

---

### 🧬 Inheritance
**What it is:** A child class acquires properties and behaviors of a parent class.  
**Why it matters:** Eliminates code duplication; promotes a logical is-a relationship hierarchy.  
**Real use:** `SavingsAccount extends BankAccount` — reuses all account logic, adds interest.  
📁 `Inheritance/`

---

### 🔁 Polymorphism
**What it is:** One interface or method name behaving differently based on context or object.  
**Why it matters:** Makes code flexible, extensible, and open for new behavior without modification.  
**Real use:** `shape.draw()` draws a Circle or Square depending on the actual object type.  
📁 `Polymorphism/`

---

### ⚠️ Exception Handling
**What it is:** Mechanism to detect, handle, and recover from runtime errors gracefully.  
**Why it matters:** Prevents crashes; separates error-handling logic from normal program flow.  
**Real use:** If a user enters letters when a number is expected, the program guides them instead of crashing.  
📁 `Exception Handling/`

---

### 🗃️ File I/O
**What it is:** Reading from and writing to files on disk during program execution.  
**Why it matters:** Enables data persistence — your data survives after the program closes.  
**Real use:** Saving bank transaction history to a file for future reference.  
📁 `File Handling/`

---

### 📦 Packages
**What it is:** Grouping related Java classes into named namespaces/folders.  
**Why it matters:** Organizes large codebases; avoids class name conflicts; enables modular design.  
**Real use:** `java.util`, `java.io` — Java's own standard library uses packages extensively.  
📁 `Packages/`

## 📊 UML Diagrams Explained

> All 5 diagram types are modeled for: **Exam Registration System** & **Banking System**

<div align="center">

| Diagram | 🎯 Purpose | 👁️ What You'll See |
|:--------|:-----------|:-------------------|
| 📌 **Use Case** | Who interacts with the system and how | Actors, use cases, system boundary, relationships |
| 📌 **Class** | Blueprint of the system's static structure | Classes, attributes, methods, associations |
| 📌 **Sequence** | How objects communicate over time | Lifelines, messages, activation bars, return calls |
| 📌 **Activity** | Step-by-step workflow and decision logic | Flow paths, decision nodes, fork/join, start/end |
| 📌 **Object** | Snapshot of actual objects at runtime | Named instances with real attribute values |

</div>
